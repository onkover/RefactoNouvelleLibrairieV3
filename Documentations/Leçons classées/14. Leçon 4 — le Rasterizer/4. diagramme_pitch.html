Pitch réel vs Width supposée — texture de 6 pixels de large, pitch = 8 pixels-équivalent

Chaque ligne fait 6 pixels utiles, mais le driver impose un pitch de 32 octets (8 "cases" de 4 octets) pour l'alignement mémoire.
Ligne y = 0 (adresse de base = pixels + 0)
Ligne y = 1 (adresse de base = pixels + pitch)
Ligne y = 2 (adresse de base = pixels + 2×pitch)
pixel réel (largeur utile = 6)
padding d'alignement (2 cases perdues/ligne)
Ce qui se passe si tu utilises y * width + x (width = 6) au lieu de y * pitch + x :

Pour y = 1, ta formule pointe vers l'octet 6 (juste après la ligne 0 supposée sans padding).
Mais la vraie ligne 1 commence à l'octet 8 (le pitch réel).
Tu écris 2 pixels trop tôt — dans le padding de la ligne précédente, qui n'existe pas visuellement.
Résultat : à partir de la ligne 2, l'image entière est décalée de 2 pixels vers la gauche. Ligne 3 : décalée de 4. Etc. — l'image "glisse" en diagonale, cumulant l'erreur ligne après ligne.
