Le problème fonctionnel

À la fin de la L05, le moteur sait où chaque sommet se projette à l’écran. Il ne sait toujours pas remplir la surface entre ces sommets. Entre « j’ai trois points » et « j’ai une image », il manque tout ce lot.

Ce que le lot doit rendre possible

  • Déterminer quels pixels appartiennent à un triangle, sans trou ni recouvrement entre triangles voisins
  • Interpoler n’importe quelle grandeur portée par les sommets (profondeur, couleur, UV, normale) en un point quelconque de la surface
  • Survivre à une caméra qui frôle ou traverse un objet, sans NaN ni géométrie qui explose
  • Décider qui est devant qui, pixel par pixel, indépendamment de l’ordre d’envoi
  • Ne dessiner que les faces tournées vers l’observateur

Pourquoi maintenant, et pas avant

  • Il faut la projection (L05) pour savoir ce que signifie « devant »
  • Il faut le reverse-Z (L05) pour que la profondeur soit utilisable loin de la caméra
  • Il faut le Viewport (L05) : c’est lui qui introduit le flip Y, donc tout le piège du sens de rotation
  • Il faut un mesh (L03) pour avoir des faces à parcourir

2La méthode : rasterisation par fonction de bord

Le lot implémente une technique nommée. Avant le pas à pas : ce qu’elle est, d’où elle vient, qui l’utilise, et pourquoi elle remplace la méthode historique.

En une phrase

Au lieu de parcourir le triangle ligne par ligne en suivant ses côtés, on teste chaque pixel indépendamment : pour chacun, trois petits calculs disent de quel côté de chaque arête il se trouve. S’il est du même côté des trois, il est dedans.

OrigineJuan Pineda, A Parallel Algorithm for Polygon Rasterization, SIGGRAPH 1988
Lienhttps://dl.acm.org/doi/10.1145/54852.378457 — exposé de référence moderne : Fabian Giesen, « A trip through the Graphics Pipeline » et « Triangle rasterization in practice » (fgiesen.wordpress.com)
Qui l’utiliseTous les GPU modernes, en silicium (NVIDIA, AMD, Intel, Apple, ARM Mali). Côté logiciel : Mesa/llvmpipe, SwiftShader, WARP, les rasterizers de Nanite (Unreal 5), et la quasi-totalité des moteurs CPU depuis 2000
Nom complet du clippingBlinn-Newell homogeneous clipping — règle d’émission de Sutherland-Hodgman, spécialisée à un plan, avec rejet trivial à la Cyrus-Beck

Pourquoi le point faible ne compte pas. Un triangle long et fin en diagonale gaspille jusqu’à 50 % des tests de sa boîte englobante. Mais chaque test coûte 3 multiplications, et 8 pixels passent dans un seul registre AVX2 : tester 8 pixels dont 4 sont rejetés coûte moins cher qu’une seule division de pente scanline. Le matériel a tranché ce débat il y a vingt ans.
Règle dictatoriale n° 1. Le rasterizer LV3 est intégralement basé fonction de bord. Aucune implémentation scanline ne sera acceptée, y compris « juste pour le wireframe ».

La formule

E(A, B, P) = (B.x − A.x) · (P.y − A.y) − (B.y − A.y) · (P.x − A.x)

C’est le double de l’aire signée du triangle (A, B, P) — autrement dit le produit vectoriel 2D des vecteurs AB et AP. Son signe dit de quel côté de la droite (AB) se trouve P.

Pour un triangle (V0, V1, V2), on calcule les trois fonctions de bord des arêtes opposées à chaque sommet :

w0 = E(V1, V2, P)   // poids de V0
w1 = E(V2, V0, P)   // poids de V1
w2 = E(V0, V1, P)   // poids de V2
Piège d’indexation. w0 est le poids du sommet V0, pas de l’arête V0V1. L’inversion est l’erreur classique au moment d’interpoler des UV — elle produit une texture qui semble « tourner » autour du triangle.

Fais passer un sommet « de l’autre côté » : l’aire change de signe, et le test d’appartenance bascule automatiquement sur l’autre comparaison. C’est ce qui rend le rasterizer indifférent au sens de rotation — le culling, lui, est traité ailleurs (étape 7).

La règle du haut-gauche, visuellement

Deux triangles partagent une arête. Un pixel tombe exactement sur cette arête (w == 0). Qui le dessine ?

Classification des arêtes partagées

Sans règle, deux issues, toutes deux fausses. Soit aucun des deux triangles ne prend le pixel → trou visible entre faces adjacentes. Soit les deux le prennent → double écriture, invisible en opaque mais catastrophique dès qu’on active EBlendMode::AlphaBlend : le bord devient deux fois plus opaque que le reste.
Règle dictatoriale n° 3. Une arête top (horizontale allant vers la gauche) ou left (descendante) inclut ses pixels de frontière ; une arête bottom ou right les exclut. Convention identique à Direct3D et OpenGL.

    for (uint8_t k = 0; k < vpf; ++k)
        cv[k].clip = MulRow(mvp, mesh->vertexPositions[ mesh->indices[base+k] ]);

    bool allIn = true;
    if (needsNearClip) {
        float d[4]; bool allOut = true;
        for (uint8_t k = 0; k < vpf; ++k) {
            d[k] = NearDistance(cv[k]);        // w − z, forme CANONIQUE
            if (d[k] >= 0.0f) allOut = false; else allIn = false;
        }
        if (allOut) continue;                 // rejet trivial
    }

    // On TRIANGULE d'abord, on clippe ensuite : borne fixe à 4 sommets,
    // aucune hypothèse de convexité sur les quads du fichier OBJ.
    for (uint8_t t = 0; t+2 < vpf; ++t)
    {
        const ClipVertex tri[3] = { cv[0], cv[t+1], cv[t+2] };
        if (allIn) {
            EmitClipTriangle(renderer, view, tri[0], tri[1], tri[2], col);
        } else {
            ClipVertex poly[kMaxClipVertices];
            const int32_t n = ClipTriangleNear(tri, poly);
            for (int32_t q = 1; q+1 < n; ++q)   // éventail, winding préservé
                EmitClipTriangle(renderer, view, poly[0], poly[q], poly[q+1], col);

}

Rasterizer.h — noyau de la fonction de bord BUG CORRIGÉ
  [[nodiscard]] LV3_FORCEINLINE constexpr float EdgeFunction(
      float ax, float ay, float bx, float by, float px, float py) noexcept
  {
-     return (bx − ax) * (py − ay) − (by − ay) * (px − ax);
+     // Forme ANTISYMÉTRIQUE : le point testé p sert de référence, donc
+     //     E(b,a,p) == −E(a,b,p)  EXACTEMENT en IEEE 754.
+     // Bénéfice secondaire : les magnitudes restent locales au pixel,
+     // ce qui supprime l'annulation catastrophique sur les sommets lointains.
+     const float ux = ax − px, uy = ay − py;
+     const float vx = bx − px, vy = by − py;

La formule vit dans le NOYAU, jamais dans les surcharges. La cascade (a,b,c) → noyau et (a,b,px,py) → noyau existe précisément pour qu’une correction se fasse à un seul endroit. Modifier une surcharge sans le noyau crée deux formules pour la même quantité : sur un triangle presque dégénéré, le culling et la rasterisation peuvent alors donner des signes opposés.

5Fonctionnement technique

Le pipeline complet, et les trois décisions structurantes qui le gouvernent.

   World ──V──▶ VIEW ──P──▶ ┌────────────────────────────────────────┐
                            │  CLIP SPACE  (x, y, z, w)              │
                            │  ▶ CLIPPING NEAR  — Sutherland-Hodgman │  avant la division
                            │    1 triangle → 0, 1 ou 2 triangles    │
                            └──────────────┬─────────────────────────┘

                            │  NDC    x,y ∈ [−1,1]    z ∈ [0,1]      │

Le point d’architecture à graver. Le clipping se fait en espace de clip, le shading en espace écran, et invW est le seul passager qui traverse la frontière. Tout le reste est soit consommé avant (les w), soit produit après (les pixels).

Décision 3 — pourquoi pas Cyrus-Beck, pourtant plus élégant

Il y a deux « Sutherland » distincts, et la confusion est courante :

AlgorithmeEntrée → sortieRéputation
Cohen-Sutherland (1967)segment → segment« algo pour débutant » — c’est celui-là : itératif, subdivision répétée
Sutherland-Hodgman (1974)polygone → polygoneRien à voir. Référence en pipeline 3D
Cyrus-Beck (1978)segment → segmentExcellent — rival de Cohen-Sutherland, pas de Sutherland-Hodgman
Liang-Barsky (1984)segment → segmentCyrus-Beck spécialisé aux volumes alignés aux axes

La démonstration. Clippe les trois arêtes d’un triangle indépendamment : l’arête V0→V1 est gardée, V1→V2 est tronquée en I₁, V2→V0 en I₂. On obtient trois segments avec un trou entre I₁ et I₂. Le segment I₁→I₂ — l’arête créée par le plan de coupe — n’appartient à aucune arête d’entrée. Aucun algorithme de clipping de segment ne peut le produire, quelle que soit son efficacité.

C’est une limite de topologie, pas de performance. Un rasterizer a besoin d’une surface fermée à remplir. C’est aussi l’explication de la retriangulation manuelle qu’il fallait écrire derrière un clipping Cyrus-Beck : ce n’était pas une étape du clipping, c’était la reconstruction topologique que l’algorithme avait détruite.
Règle dictatoriale n° 20. Le choix de l’algorithme de clipping suit la topologie de sortie, pas la réputation. Polygone → Sutherland-Hodgman en 4D homogène. Segment → Liang-Barsky (ray/AABB, slab method) ou Cyrus-Beck (volume convexe non aligné). Ces deux-là restent les bons outils pour Ray::Intersect et ScreenPointToRay.

Ce qui est tout de même récupéré de Cyrus-Beck : le rejet / acceptation trivial en tête de fonction, et la formulation paramétrique t = dA / (dA − dB) — qui est sa formule, réécrite avec les distances pré-calculées au sommet plutôt que des produits scalaires par arête.

Pourquoi personne ne l’a vu pendant toute une leçon. La couleur était un hash par face. Sur un objet convexe fermé : silhouette identique, profondeur cohérente, couleurs arbitraires dans les deux cas. Un cube rendu à l’envers ressemble exactement à un cube.

7.3 — 124 trous sur les coutures du clipping bug n° 21

Deux triangles adjacents partagent une arête, mais la parcourent en sens opposé :

Triangle A traverse 2 → 0 :  t = d2/(d2−d0)  →  I20 = Lerp(v2, v0, t)
Triangle B traverse 0 → 2 :  t = d0/(d0−d2)  →  I02 = Lerp(v0, v2, t)

Mathématiquement I20 == I02. En IEEE 754, presque jamais bit à bit : deux séquences d’opérations différentes sur les mêmes données.

La mesure

[COVERAGE] doubles=0  trous=124
[COVERAGE] premier (215,40)  dernier (90,165)

Δx = −125    Δy = +125     →  pente exactement −1
124 trous pour 125 pas     →  UN pixel par ligne, sans exception

Une droite d’un pixel de large, continue. doubles = 0 : les deux triangles se rejettent mutuellement. Signature sans ambiguïté de la fissure de couture — et la localisation a désigné la cause avant qu’on ouvre le code.

L’antisymétrie supprime 97 % du défaut : elle règle l’amplification, car les intersections tombaient à environ 9 900 pixels hors viewport, où l’annulation catastrophique transforme un ULP en plusieurs pixels. // Ordre total DÉTERMINISTE sur les coordonnées de clip.
// Deux triangles adjacents parcourant la même arête en sens opposé
// calculent alors le MÊME point, bit à bit.
[[nodiscard]] LV3_FORCEINLINE bool ClipLess(const Vec4f& a, const Vec4f& b) noexcept
{
    if (a.x != b.x) return a.x < b.x;
    if (a.y != b.y) return a.y < b.y;
    if (a.z != b.z) return a.z < b.z;
    return a.w < b.w;
}
Règle dictatoriale n° 23. Un point d’intersection partagé entre deux primitives doit être calculé dans un ordre canonique, indépendant du sens de parcours. Là où l’arithmétique flottante ne garantit pas l’égalité, une convention arbitraire mais universelle la fabrique — exactement comme la règle du haut-gauche au niveau du pixel.

7.4 — Le champ oublié bug n° 19

invW0/1/2 ajoutés à FragmentContext, mais Renderer::DrawTriangle ne les recopiait pas. Aucune erreur de compilation, aucune erreur de lien.

den  = b0·0 + b1·0 + b2·0 = 0

Pourquoi ces tests-là, et pas d’autres

Test 4 — pourquoi les deux ordres

Le Z-buffer doit trancher, pas l’ordre de soumission. Un test à sens unique peut passer par coïncidence : si TestAndSet laissait tout passer, le premier ordre donnerait quand même la bonne image. Les deux ordres donnant le même résultat, c’est la définition opérationnelle d’un Z-buffer qui fonctionne.

Test 10 — pourquoi un contre-exemple positif

Une suite qui ne vérifie que des rejets serait entièrement satisfaite par void RasterizeTriangle(...) { return; }. Le cas « triangle valide → au moins 1 fragment » est ce qui donne du sens aux cinq cas négatifs.

Test 9 — le seul qui attrape les fissures

Une fissure d’un pixel ne crashe pas, ne produit pas de NaN, et se perd dans le bruit d’une scène animée. Il faut compter, pas regarder. Le critère du trou — un pixel vide dont les quatre voisins sont pleins — rend le test insensible aux bords : seules les fissures intérieures sont comptées.

Test 6 — pourquoi un mode fautif

Voir des bandes droites ne prouve rien tant qu’on n’a pas vu à quoi ressemble l’erreur. Si les deux modes donnaient la même image, c’est que la version « correcte » ne ferait rien. Pour valider une correction, il faut pouvoir produire le défaut à volonté.

Prédictions du lot appairé

Ce que le lot suivant (texturing) devra observer si celui-ci est correct :

  • Un damier sur sol incliné à 80° doit avoir ses carreaux rétrécissant avec la distance, et aucun pli sur la diagonale des quads

9.5 — Principes méthodologiques dégagés

  1. « Ça s’affiche » n’est jamais un critère de validation. Il faut une sortie dont la valeur a un sens géométrique vérifiable.
  2. Pour rendre visible une erreur continue, il faut un signal discontinu. Un dégradé cache les petites erreurs ; des bandes ou un damier les amplifient.
  3. Compter, pas regarder. Deux fois de suite, la mesure a trouvé ce que l’œil ne pouvait pas voir — et la localisation a désigné la cause avant qu’on ouvre le code.
  4. Pour valider une correction, il faut pouvoir produire le défaut à volonté.
  5. Mesurer avant de garder. La bissection a prouvé que les deux correctifs étaient nécessaires — pas un de trop, pas un de moins.
  6. Une assertion jamais vue échouer n’est pas prouvée.
  7. Quand un algorithme oblige à écrire une passe de réparation derrière lui, c’est qu’il ne calculait pas ce qu’on voulait.
  8. Comparer la topologie de sortie avant de comparer les performances.
  9. Une donnée écrite dans un fichier de configuration et jamais lue est un mensonge que rien ne compile.
  10. Quand une information doit être répétée à deux endroits sans vérification automatique, il faut soit la dériver, soit l’asserter.
