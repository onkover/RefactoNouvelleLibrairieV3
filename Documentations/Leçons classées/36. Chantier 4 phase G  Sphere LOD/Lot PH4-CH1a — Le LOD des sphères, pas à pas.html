0.1 · Pourquoi ce lot

Le chantier LOD des rochers (lot PH4-CH1) avait fait descendre les 1 200 roches visibles de 168 à 8 faces. Restaient les planètes et les lunes : 40 sphères dessinées en pleine résolution, qui portaient à elles seules 88 % des faces encore soumises. Ce lot leur donne des niveaux de détail, et en profite pour vérifier qu’une exigence posée par Onky est tenue : tout mesh, présent ou futur, doit pouvoir avoir ou non une chaîne de LOD, sans code particulier.

Le lot est court en code (aucune ligne du moteur ne change) mais riche en leçons, parce qu’il pose trois questions que les rochers n’avaient pas posées :

  1. Une sphère se mesure-t-elle comme un rocher ? Non : sur une surface lisse, l’erreur maximale ne se cache pas au même endroit. La mesure le montre, et une vérification analytique indépendante le confirme.
  2. Qui décide de la résolution d’une planète ? L’auteur de la scène avait choisi sphere_mid pour Mercure. Une chaîne a-t-elle le droit d’aller plus haut quand la planète grossit à l’écran ? Le lot tranche : non, L0 est un plafond.
  3. Que reste-t-il à gagner ? La mesure montre que Render ne suit plus le nombre de faces : un coût fixe par objet domine désormais. C’est la fin du chantier LOD sur cette scène, et le passage au chantier Clear.

Trois jours après la clôture, une observation d’Onky (« je vois le changement de niveau d’une frame à l’autre ») a ajouté une quatrième leçon : ε garantit la silhouette, pas la couleur. Elle est racontée en fin de lot (étape 14) et dans le laboratoire 1.5.

En une phrase. Une chaîne de LOD est une optimisation qui ne doit jamais changer l’image de plus de τ : elle ne descend que sous le choix de l’auteur, elle se fabrique de la façon la plus exacte disponible, et tout ce qui est affiché doit être une propriété de la surface, jamais de la numérotation du maillage.

M · La méthode : fabriquer, mesurer et plafonner une chaîne

M.1 · L’idée, vulgarisée

Une sphère dessinée avec des triangles est un polyèdre : vue de loin, sa silhouette est un polygone. L’écart entre ce polygone et le vrai cercle s’appelle la flèche (le mot vient de l’arc et de sa corde : la flèche est la hauteur de l’arc au-dessus de la corde). Plus il y a de triangles, plus la flèche est petite. Le LOD remplace une sphère fine par une sphère grossière tant que la flèche, ramenée en pixels, reste sous un demi-pixel. Pour une sphère, la règle devient presque parlante : « sphere_lo suffit tant que l’astre fait moins de 15 pixels de rayon ».

M.2 · Les deux façons de fabriquer un niveau

VoiePrincipeQuandSource
Ré-échantillonnage ("resample")On rappelle la fonction qui a créé L0 avec une grille plus grossière. La surface est exactement la même ; seuls les points d’échantillonnage changent.Sphères, rochers, terrains : tout mesh issu d’une fonctionPratique standard des générateurs procéduraux ; utilisée pour les rochers (A14 § 3.1)
Simplification par quadriques ("qem")On fusionne des arêtes une à une, en choisissant chaque fois celle dont la disparition déforme le moins la surface, mesurée par une somme de distances aux plans voisins (une quadrique par sommet).Mesh modélisé ou importé, sans fonctionM. La validation prévue du QEM utilise les sphères comme banc d’essai : simplifier sphere_hi jusqu’à 960, 288 et 64 faces, et comparer son ε à celui du ré-échantillonnage exact au même nombre de faces. Le QEM devrait même gagner : une sphère UV gaspille des triangles minces aux pôles.

M.3 · La mesure de ε, et sa vérification

Comme pour les rochers : on lance des rayons depuis le centre dans 100 000 directions aléatoires, plus des directions ciblées ; pour chaque rayon on mesure la distance à la surface de L0 et à celle de Lk ; εk est le plus grand écart, ×1,1, arrondi vers le haut au dix-millième. Le lot ajoute deux choses :

  • Un ciblage sur les centres de faces : sur une sphère, la flèche est maximale au centre des triangles, pas aux sommets (où l’écart est nul, puisque les sommets sont sur la sphère).
  • Une vérification analytique indépendante : pour un triangle dont les sommets sont sur la sphère unité, le point le plus enfoncé est le pied de la perpendiculaire abaissée du centre sur son plan ; la flèche vaut 1 − |n·a| (n normale unitaire, a un sommet), si ce pied tombe dans le triangle. Aucun rayon, aucun tirage.

M.4 · Pourquoi ε se lit en pixels de rayon

Le moteur admet le niveau k si εk × q ≤ τ, avec q le nombre de pixels par unité locale. Une sphère de rayon local 1 a pour rayon apparent R = q pixels. Donc :

niveau k admis  ⇔  R ≤ τ / ε_k        (τ = 0,5 px)
mid  : 0,5 / 0,0106 = 47,2 px      lo  : 0,5 / 0,0330 = 15,2 px
12×6 : 0,5 / 0,0698 =  7,2 px      8×5 : 0,5 / 0,1335 =  3,7 px      6×4 : 0,5 / 0,2030 = 2,5 px

La flèche est proportionnelle au rayon : ε ne dépend pas de l’échelle du Transform. Pour un rocher, ces seuils n’ont pas d’expression aussi simple (son rayon local varie autour de 1).

M.5 · Le plafond : une décision de contenu, pas d’optimisation

Un LOD est une optimisation conservatrice : il remplace ce que l’auteur a demandé par quelque chose d’indiscernable et de moins cher. Monter au-dessus du choix de l’auteur serait l’inverse : plus cher et différent. Les moteurs du commerce font la même séparation : dans Unity, le premier niveau d’un LODGroup est le mesh de l’artiste ; dans Unreal, le niveau 0 d’un StaticMesh est l’asset importé. Une résolution plus fine est un autre asset, choisi par l’auteur.

1 · Laboratoires — voir avant le code

Tout est calculé dans la page. Les sphères sont générées par la même fonction que gen_meshes.py (uv_sphere, couture et pôles compris). Les comparaisons de la sélection sont faites en float32 (Math.fround), comme dans le moteur.

1.1 · La flèche : une sphère facettée rasterisée

Choisis une grille et un rayon à l’écran. La sphère est projetée (vue orthographique), puis chaque centre de pixel est testé contre la silhouette du polyèdre et contre le vrai disque. Les pixels manquants sont ceux que le cercle couvre et pas le polyèdre. La flèche maximale est calculée analytiquement, triangle par triangle.

1.2 · Trois chaînes, un rayon apparent

Fais varier le rayon apparent R. Pour chaque descripteur, le moteur compte les comparaisons q′ ≤ invEps[i] vraies (SelectLodLevel, en float32). La case cerclée est le niveau dessiné. « Flèche » est l’écart réel du niveau dessiné à la vraie sphère, en pixels ; en rouge s’il dépasse τ. Deux cases à cocher montrent la décision écartée (une chaîne unique qui monte) et un amendement postérieur (le dessin en point, A20).

1.3 · Mesurer ε : où se cache le maximum ?

Sur un rocher, 400 directions aléatoires sous-estimaient ε de 46 % (lot PH4-CH1, laboratoire 1.2). Ici, on cherche la flèche de la sphère choisie par N rayons tirés au hasard, et on compare au maximum analytique. Le graphe montre le meilleur maximum trouvé en fonction du nombre de rayons. Les rayons sont lancés pour de vrai contre les triangles (Möller-Trumbore, en double précision).

1.4 · La loi de coût : un rapport n’est pas une pente

Les deux nuages sont les deux scènes du lot M13 (médianes des 4 runs). La droite pointillée est le modèle « coût constant par face » tiré de la Référence I (Render ÷ faces) ; la droite pleine est le modèle à deux termes mesuré frame par frame. Fais glisser F pour voir ce que chaque modèle prédit.

1.5 · La bascule vue par l’œil : silhouette ou couleur ?

Une sphère est rasterisée au rayon exact du seuil, au niveau fin (frame n), puis au niveau grossier (frame n+1). La troisième image montre les pixels qui changent. Choisis la façon de colorer : le hash de l’indice de face (mode Solid du moteur), une couleur de matériau, la profondeur (mode Depth), ou un éclairage Flat, Gouraud ou Phong (futur chantier shading).

2 · La partie technique

2.1 · La sphère UV : une fonction, donc un ré-échantillonnage exact

uv_sphere(seg, rings) pose (rings + 1) × (seg + 1) sommets sur la sphère unité. Deux corrections, déjà dans le lot SG, conditionnent tout ce qui suit : la couture (une colonne dupliquée, même position, u = 1 au lieu de 0) et les pôles (une rangée complète de sommets confondus, chacun avec son u ; un seul triangle par quad dégénéré). 2.2 · La flèche analytique : scalaire et pendant AVX2

Pour un triangle (a, b, c) dont les sommets sont sur la sphère unité, n = (b − a) × (c − a) normalisé, d = |n·a| est la distance du centre au plan. Le point du plan le plus proche du centre est p = (n·a) n. S’il tombe dans le triangle (coordonnées barycentriques ≥ 0), la flèche du triangle vaut 1 − d. Le maximum sur les faces est la flèche du maillage. Ce calcul a servi à vérifier la mesure par rayons ; il n’entre pas dans le moteur.

Scalaire — outil hors ligne
// Fleche max d'un maillage dont les sommets sont sur la sphere unite.
float MaxSag(const Vec3f* V, const uint32_t* idx, size_t nFaces)
{
    float best = 0.0f;
    for (size_t f = 0; f < nFaces; ++f)
    {
        const Vec3f a = V[idx[3*f]], b = V[idx[3*f+1]], c = V[idx[3*f+2]];
        const Vec3f e1 = b - a, e2 = c - a;
        Vec3f n = cross(e1, e2);
        const float len = n.length();
        if (len <= NEAR_ZERO) continue;          // quad degenere au pole
        n = n * (1.0f / len);
        const float s  = dot(n, a);              // n.a : distance signee
        const Vec3f v2 = n * s - a;              // pied p - a
        // barycentriques de p dans (a, e1, e2)
        const float d00 = dot(e1,e1), d01 = dot(e1,e2), d11 = dot(e2,e2);
        const float d20 = dot(v2,e1), d21 = dot(v2,e2);
        const float den = d00*d11 - d01*d01;
        const float v = (d11*d20 - d01*d21) / den;
        const float w = (d00*d21 - d01*d20) / den;
        if (v >= 0.0f && w >= 0.0f && v + w <= 1.0f)
            best = std::max(best, 1.0f - std::fabs(s));
    }
    return best;
}
Pendant AVX2 — pédagogique, non appliqué
// 8 faces a la fois, sommets en SoA (ax[8], ay[8], ...),
// comme les plans de B5 (FacePlanesSoA).
__m256 MaxSag8(const FaceSoA8& F, __m256 best)
{
    // aretes e1 = b - a, e2 = c - a, couloir par couloir
    const __m256 e1x = _mm256_sub_ps(F.bx, F.ax), e1y = _mm256_sub_ps(F.by, F.ay),
                 e1z = _mm256_sub_ps(F.bz, F.az);
    const __m256 e2x = _mm256_sub_ps(F.cx, F.ax), e2y = _mm256_sub_ps(F.cy, F.ay),
                 e2z = _mm256_sub_ps(F.cz, F.az);
    // n = e1 x e2 (sans FMA : mul puis sub, comme EdgeFunction)
    const __m256 nx = _mm256_sub_ps(_mm256_mul_ps(e1y,e2z), _mm256_mul_ps(e1z,e2y));
    const __m256 ny = _mm256_sub_ps(_mm256_mul_ps(e1z,e2x), _mm256_mul_ps(e1x,e2z));
    const __m256 nz = _mm256_sub_ps(_mm256_mul_ps(e1x,e2y), _mm256_mul_ps(e1y,e2x));
    // |n| et n.a : la fleche vaut 1 - |n.a| / |n|
    const __m256 len = _mm256_sqrt_ps(Dot3(nx,ny,nz, nx,ny,nz));   // vraie racine, pas rsqrt
    const __m256 s   = _mm256_div_ps(Dot3(nx,ny,nz, F.ax,F.ay,F.az), len);
    const __m256 sag = _mm256_sub_ps(_mm256_set1_ps(1.0f), Abs(s));
    // masque : pied dans le triangle ET |n| non nul (faces degenerees du pole)
    const __m256 in  = _mm256_and_ps(FootInside8(F, nx,ny,nz, s, len),
                       _mm256_cmp_ps(len, _mm256_set1_ps(NEAR_ZERO), _CMP_GT_OQ));
    // max couloir par couloir ; reduction horizontale apres la boucle
    return _mm256_max_ps(best, _mm256_and_ps(in, sag));
}

2.3 · La mesure par rayons : scalaire et pendant AVX2

Le rayon issu du centre dans la direction D coupe chaque triangle (au plus un, la sphère facettée est convexe et étoilée). L’intersection de Möller-Trumbore donne la distance t ; on garde la plus petite. ε = max |tk(D) − t0(D)|. Le script (NumPy) traite toutes les directions en bloc pour un triangle à la fois.

Scalaire — une direction, tous les triangles
// Origine au centre (0,0,0) : s = -a, donc les produits se simplifient.
float RayRadius(Vec3f D, const Vec3f* V, const uint32_t* idx, size_t nFaces)
{
    float best = std::numeric_limits<float>::infinity();
    for (size_t f = 0; f < nFaces; ++f)
    {
        const Vec3f a = V[idx[3*f]];
        const Vec3f e1 = V[idx[3*f+1]] - a, e2 = V[idx[3*f+2]] - a;
        const Vec3f p = cross(D, e2);
        const float det = dot(p, e1);
        if (std::fabs(det) <= 1e-12f) continue;   // rayon parallele au plan
        const float inv = 1.0f / det;
        const Vec3f s = -a;
        const float u = dot(p, s) * inv;
        const Vec3f q = cross(s, e1);
        const float v = dot(D, q) * inv;
        const float t = dot(e2, q) * inv;
        if (u >= 0 && v >= 0 && u + v <= 1 && t > 0)
            best = std::min(best, t);
    }
    return best;                                   // +inf = trou : assertion
}
Pendant AVX2 — 8 directions à la fois
// Un triangle diffuse ses aretes (broadcast) ; 8 directions D en SoA.
// Le meme triangle est teste contre 8 rayons : aucune lecture dispersee.
void RayRadius8(const Dir8& D, const Tri& T, __m256& best)
{
    const __m256 e1x = _mm256_set1_ps(T.e1.x), ... ;           // 9 diffusions
    const __m256 px = _mm256_sub_ps(_mm256_mul_ps(D.y, e2z), _mm256_mul_ps(D.z, e2y));
    // ... py, pz : p = D x e2
    const __m256 det = Dot3(px,py,pz, e1x,e1y,e1z);
    const __m256 ok  = _mm256_cmp_ps(Abs(det), _mm256_set1_ps(1e-12f), _CMP_GT_OQ);
    const __m256 inv = _mm256_div_ps(_mm256_set1_ps(1.0f), det);  // division, jamais rcp
    const __m256 u = _mm256_mul_ps(Dot3(px,py,pz, sx,sy,sz), inv); // s = -a diffuse
    const __m256 v = _mm256_mul_ps(Dot3(D.x,D.y,D.z, qx,qy,qz), inv); // q = s x e1 diffuse
    const __m256 t = _mm256_mul_ps(_mm256_set1_ps(dot(T.e2, q)), inv);
    // masque : ok, u >= 0, v >= 0, u + v <= 1, t > 0 ; puis min masque
    const __m256 hit = ...;
    best = _mm256_blendv_ps(best, _mm256_min_ps(best, t), hit);
}

Les deux √3 se compensent ; il reste wMin = wC − √3·s, plus proche que le vrai bord de la sphère (wC − s). q′ est donc légèrement surestimé, du côté sûr : le moteur choisit plutôt un niveau plus fin. L’écart compte peu pour un objet lointain (wC ≫ s).
